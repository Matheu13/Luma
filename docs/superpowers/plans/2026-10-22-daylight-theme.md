# Daylight Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Luma's sixth theme, Daylight: an Apple-TV-style home with a big top area for the focused favourite, rounded tiles in rows with every app, an animated lift-and-tilt focus, and a light look.

**Architecture:** Everything except the wallpaper lives in `MainActivity.java`, following its existing dense style.
- The theme is index 5 (`DAYLIGHT`).
- In Daylight, `visible()` returns favourites followed by the other apps. A small set of helpers keeps moves and options within the right list.
- Drawing branches into new `daylightHome`/`daylightCard` methods inside `Screen`. Animation is time-based in `onDraw`, using `postInvalidateOnAnimation` while anything moves.
- The wallpaper is generated by a Pillow script, like the launcher icon.

**Tech Stack:** Java 8 (`javac --release 8`), Android SDK 35 tools without Gradle (`tools/build.ps1`), Canvas drawing, Python 3 + Pillow, and ADB-driven `tools/regression-audit.py` as the test suite (run against the dev Fire TV).

**Spec:** `docs/superpowers/specs/2026-10-22-daylight-theme-design.md`

## Global Constraints
- Java language level 8; `minSdkVersion 26`; no new permissions, no new libraries, no Gradle.
- The other five themes (`lunar`, `aurora`, `cinema`, `prism`, `nebula`; indices 0–4) must draw and behave exactly as in 1.1.1: a static focus outline with no motion.
- Daylight's theme index is 5, its key is `daylight`, its title is `Daylight`, and its accent is `0xff3d7cf5`.
- No Apple artwork, names or icons. The wallpaper is original and generated, with a crisp, cool palette (the user prefers cool tones).
- The design space is 1672×941, as in the other themes.
- Match the surrounding code: dense one-line Java, comments only where a choice needs explaining.
- Version: Daylight ships as **1.2** (versionCode 14). The README's planned TV setup becomes "Luma 1.3".
- Tests are `tools/regression-audit.py` checks run on the dev Fire TV (`LUMA_DEVICE` from `tools/local.json`). Build and install with `powershell -File tools\build.ps1`. The build deletes `build/`, so audit screenshots are regenerated each run.

## Review Focus
1. **Fewer than eight apps installed** (nothing below the favourites row). Down from row 1 must do nothing, with no crash and no blank scroll. → Task 2, step 6 (code review check, since the device can't be put in this state safely).
2. **An app installed or removed while Daylight is showing** (`packageObserver` → `refreshApps`). The per-tile animation state must resize with the list, never index past it. → Task 4, step 5.
3. **Move mode at the boundary between the dock and the rest.** Moving the last favourite Down must not swap it with a non-favourite. → Task 2 audit check "Daylight move stays in the dock row".
4. **Leaving Daylight mid-animation** (switching theme, opening All apps, Home pressed). The scroll and lift state must reset, and no motion may leak into other themes. → Task 4 audit check "Other themes stay static".
5. **Long app names under the focused tile** (e.g. "FireTV Troubleshooting"). They must be ellipsized to the tile width plus margin, not overlap neighbours. → Task 3, step 4.

**Interfaces:**
- Consumes: `daylight-wallpaper.png` (Task 1).

### Task 3: Top area and scrolling

- [ ] **Step 4: Implement `daylightHome`.**
  - **Scroll:** `scrollTarget = row==0 ? 0 : 300+160*row`. Ease `scroll` towards it with a 200 ms exponential approach based on frame time. While `|scroll-scrollTarget|>0.5`, keep animating. Draw tiles and the top area translated by `-scroll`.

  - **Top bar:** drawn unscrolled. Text and gear are white while `scroll<100`, and `0xff1c1f26` once scrolled.

### Task 4: Lift-and-tilt focus (Daylight only)

**Files:**
- Modify: `app/src/com/dhyn/tvhome/MainActivity.java`: `Screen` (lift state, tilt, `daylightCard` focus drawing), `onKeyDown` (record the arrow direction).
- Test: `tools/regression-audit.py`.

**Interfaces:**
- Consumes: `daylightCard`, `daylightHome`, scroll state (Task 3).
- Produces:
  - `float[] Screen.lift` (0..1 per visible index);
  - `int tiltX, tiltY` (−1/0/1, set by the last arrow in Daylight);
  - `long lastFrame`.

- [ ] **Step 1: Write the failing audit checks.**
  - `'Daylight focus animates smoothly'`:
    1. `sh('dumpsys','gfxinfo','com.dhyn.luma','reset')`;
    2. press `key(22,0.4)` ×6 and `key(21,0.4)` ×6;
    3. parse `Janky frames: N (P%)` from `dumpsys gfxinfo com.dhyn.luma`;
    4. pass if `P < 10` and `Total frames rendered` is above 30. (Above 30 proves animation frames were drawn, so it fails while the focus is static.)
  - `'Other themes stay static'`: after `choose_theme('Nebula')`, run the same reset and presses, then pass if `Total frames rendered` is 24 or fewer (about one frame per key press, no animation frames).
- [ ] **Step 2: Run the audit and verify the Daylight check fails** (too few frames rendered).
  Run: `powershell -File tools\build.ps1; python tools\regression-audit.py`
  Expected: `FAIL Daylight focus animates smoothly`, `PASS Other themes stay static`.
- [ ] **Step 3: Implement the lift state.**
  - Each frame in Daylight, move `lift[i]` towards `i==selected&&nav<0 ? 1 : 0` at `dt/150ms`, with ease-out `1-(1-t)^3` applied when drawing.
  - In `onKeyDown`, set `tiltX`/`tiltY` from the arrow in Daylight (left −1, right +1, up −1, down +1).
  - Keep `postInvalidateOnAnimation` while any `lift` is strictly between 0 and 1, or the tilt is easing back. The tilt eases back to 0 over 300 ms.
- [ ] **Step 4: Implement focus drawing in `daylightCard`** when `lift>0`:
  - scale `1+0.12*e` about the tile centre;
  - **shadow:** 4 concentric round rects, grown by 6/12/18/24 px, alpha `0x10`, offset y `10*e`, drawn before the tile;
  - **tilt:** `android.graphics.Camera`, `rotateY(4*tiltX*e)` and `rotateX(-4*tiltY*e)` about the tile centre, applied via `getMatrix` + `concat`;
  - **shine:** a diagonal `LinearGradient` from `alpha(0xffffffff,(int)(0x40*e))` at the top-left to transparent at the centre;
  - draw no outline in Daylight once the lift is visible (`e>0.05`).
- [ ] **Step 5: Handle list changes and leaving Daylight.**
  - At the start of `daylightHome`, if `lift==null||lift.length!=visible().size()`, reallocate it (new entries 0, the selected one 1). This covers apps installed or removed while showing.
  - When `daylight()` is false, set `lift=null`, `tiltX=tiltY=0`, and never call `postInvalidateOnAnimation` for Daylight state.
- [ ] **Step 6: Run the audit.**
  Run: `powershell -File tools\build.ps1; python tools\regression-audit.py`
  Expected: all checks PASS. Also watch the TV while it navigates: the focus should lift smoothly, with no stutter.
- [ ] **Step 7: Commit.**
